# Site Watch

Монитор доступности и поисковой аналитики для сайтов портфолио. FastAPI выполняет HTTP-проверки, SQLite хранит локальную историю. На панели видны последний ответ, доля успешных проверок за 24 часа или 7 дней, медиана скорости, эпизоды сбоев, график и журнал. Все значения считаются по фактическим наблюдениям; количество проверок указано рядом с процентом.

[Открыть панель на GitHub Pages](https://an724275-hash.github.io/site-watch-python-js/). GitHub Actions проверяет адреса примерно каждые 30 минут и сохраняет историю в отдельной ветке `site-watch-history` перед публикацией страницы. Очистка кэша или сбой развёртывания её не стирают. На панели остаются до 400 снимков за последние семь дней. Пропущенные запуски не заполняются: дата последней проверки и число наблюдений всегда показаны. Pages не запускает FastAPI; ручная проверка через API доступна только локально.

Задание `collect` в workflow Pages требует `contents: write` для сохранения истории; новый токен или секрет не нужен. Это разрешение действует на содержимое всего репозитория, а не только одной ветки; скрипт записывает только `history.json` в `site-watch-history`. Задание `deploy` получает `pages: write` и `id-token: write`, без права записи содержимого репозитория, и публикует подготовленный артефакт только после успешного `collect`. Оба задания используют окружение `github-pages` и его действующие правила допуска; workflow эти правила не меняет.

При первом запуске `collect` переносит доступную историю из прежнего кэша, затем кэш больше не используется. Если доступной копии в кэше нет, workflow выводит предупреждение и начинает историю с новой проверки. Ошибка чтения существующей ветки, повреждённый JSON или отказ записи останавливают публикацию вместо незаметного сброса данных. Ветку `site-watch-history` не следует удалять; её Git-коммиты сохраняют и более старые снимки.

Раздел «Поисковые запросы» принимает CSV-экспорт Google Search Console или Яндекс Вебмастера с колонками запросов, кликов и показов. Он считает клики, показы, CTR и среднюю позицию, даёт искать по запросам. CSV обрабатывается только в памяти вкладки и исчезает после её обновления или закрытия, без отправки на GitHub. Реального подключения к аккаунтам поисковых сервисов нет; для него потребуются авторизация и серверная интеграция. Период SEO-данных определяется экспортом, а не Site Watch.

## Проекты и трактовка проверок

В мониторинге семь сайтов: портфолио, лендинг мероприятия, GoldenFix, Макрос Молл, Китайский магазинчик, Nordic Timbers и 3D-утка. Адреса заданы в `targets.json`. Идентификаторы прежних четырёх проектов сохранены; история новых начинается с их первой проверки.

- Успешным считается только HTTP 2xx. Проверка следует максимум пяти HTTPS-редиректам внутри исходного домена (допускается вариант с www). Другой хост, порт, учётные данные в адресе или переход на HTTP останавливают проверку с объяснением.
- HTTP 401/403/429 показываются как ограничение доступа, а не подтверждённый сбой сайта. Исторические 3xx больше не считаются подтверждением успешной конечной страницы.
- Замер включает получение заголовков ответа и разрешённые редиректы, но не полную загрузку страницы и не выполнение JavaScript. HTML-тело не скачивается целиком. Ошибки сети показаны в журнале, их время ожидания не изображается как скорость HTTP-ответа.
- Снимок старше трёх часов помечается устаревшим. Интерфейс читает статусы и историю из одного файла, поэтому разные версии двух JSON не смешиваются. При ошибке обновления последний загруженный снимок остаётся виден с предупреждением.
- Доля успеха считается только по наблюдениям с определённым HTTP-результатом: успехом или ошибкой ответа. HTTP 401/403/429, сетевые ошибки без HTTP-ответа, непроверенные редиректы и неизвестные результаты исключаются из знаменателя; их количество показано отдельно. Если все наблюдения неопределённые, выводится «Нет оценки», а не 0%. Сетевой таймаут остаётся в журнале, но сам по себе не доказывает простой сайта для посетителей. Неопределённый результат также не доказывает восстановление после ошибки. Пропущенные проверки не восстанавливаются.

CSV-импорт разделён по паре «сайт + источник». Есть поиск, сортировка, страницы по 25 строк и удаление импорта. Ограничения: 5 МБ и 5000 строк. Некорректные числа, незакрытые кавычки и превышение лимита отклоняются без замены предыдущих данных. Пустая позиция не превращается в ноль. Таблица не обрезается молча.

Светлая и тёмная темы сохраняют только выбор оформления в localStorage. SEO-данные остаются в оперативной памяти вкладки.

## Запуск

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
uvicorn app:app --reload
```

Откройте `http://127.0.0.1:8000`. Проверки идут при запуске, затем раз в пять минут. Дополнительную проверку можно запустить через `POST /api/targets/{id}/check`. Локальная история доступна через `/api/targets`.

Тесты: `python -m pytest -q` и `node --test tests/analytics.test.mjs`.

Список сайтов хранится в `targets.json`; после изменения перезапустите сервер. Интерфейс не принимает произвольные адреса. Это ограничение защищает от использования монитора для запросов к внутренним адресам. Для публичного развёртывания используйте только доверенный файл конфигурации и ограничьте доступ к API ручной проверки. HTTP 403 означает отказ автоматическому клиенту и не доказывает, что сайт недоступен людям.

Переменные окружения: `SITE_WATCH_DB`, `SITE_WATCH_TARGETS`, `SITE_WATCH_INTERVAL` (секунды, минимум 30).
